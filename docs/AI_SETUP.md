# AI 模型服务配置

AI 是**能力增强，不是运行前提**。不配任何模型，平台照样能跑完整流程并出报告，
只是「看截图认政策入口」这类需要看图判断的环节会走规则策略。

---

## 1. 配置放在哪、为什么

模型连接（地址 / 模型名 / 密钥）是**平台级**配置，在
**系统状态 → AI 模型服务**里管：可以存多套、随时启用、点「测试」当场验证、用完删除。

「开哪些 AI 环节」「多久问一次模型」是**任务级**策略，留在「新建任务」页 ——
因为那是这次检测的取舍，不是环境。

一个任务的模型来自哪，优先级是：

```
启用的配置档案  >  config.yaml 的 ai 段  >  内置默认（none）
```

档案优先，是因为任务里可能还留着旧版本的地址；冲突时以档案为准并写日志，
不悄悄按旧的跑 —— 否则你会以为配置没保存成功。

---

## 2. 三种接法

### Ollama（本机 / 内网，无密钥）

```
类型：Ollama
地址：http://127.0.0.1:11434
文本模型：qwen2.5:7b
视觉模型：qwen2.5vl:7b      ← 要「看截图」就必须填一个多模态模型
```

判断一个 Ollama 模型能不能看图：`ollama show <model>` 里有没有 `vision` 能力。
平台测试时会读模型能力清单，能确认就说确认，不能确认就只说「看起来支持」。

**上下文预算**：默认 `num_ctx` 8192。超限时服务端**静默截尾**（不报错），
模型只看到一部分，而报告可能写着「已分析全文」—— 这是最危险的一类假阴性。
所以长文一律走分块 map-reduce，不做「塞进去试试」。

### DeepSeek（云端，按量计费）

```
类型：DeepSeek
地址：留空 = https://api.deepseek.com
文本模型：deepseek-flash
视觉模型：deepseek-flash
密钥：sk-...
```

**能力按模型分，不按厂商分**（官方价格表的 FEATURES 列）：

| 模型 | 视觉 |
|---|---|
| `deepseek-flash`（V4.1-Flash） | ✓ 支持图片输入 |
| `deepseek-v4-pro`（V4-Pro） | ✗ 只读文本 |

所以可以「文本用 v4-pro（推理更强）+ 视觉用 flash」。
视觉模型留空时平台会自动用 `deepseek-flash`，**不会**沿用 v4-pro ——
不然每次带图调用都会 400，然后静默回退。

> `deepseek-chat` / `deepseek-reasoner` 已不在现行模型表里；
> 旧配置里留着这两个名字的，保存时会自动改写成 `deepseek-flash`。

### 其他 OpenAI 兼容接口（vLLM / LM Studio / 中转）

```
类型：其他 OpenAI 兼容接口
地址：https://your-host/v1
模型：服务端部署的名字
密钥：按需
```

任何暴露 `/v1/chat/completions` 的服务都能接。是否支持图片由服务端模型决定，
平台无法从接口核实，所以配置列表上不会替你打「能看图」的勾。

## 3. 费用与速度

| 环节 | 调用量 | 说明 |
|---|---|---|
| 政策全文深读 | 按正文长度分块，4 路并发 | 一份长政策约 5~15 次调用 |
| 看截图定位政策入口 | 每次 1 张图 | 只在首启阶段，通常个位数 |
| AI 指挥遍历 | `ui_agent_every` 步一次，上限 `ui_agent_max_calls` | 默认 5 步一次、最多 8 次 |

两个旋钮就是成本闸门。**「每步都问」在真实环境里代价很高**：
本地 CPU 推理每步几十秒，云端按量计费。默认 5 步一次，中间步骤走规则遍历，
效果几乎不损失。

速度不是这个平台的优化目标 —— 为了准确率可以多花时间。但「配了 AI 却卡住」
是不能接受的，所以有一次调用的硬超时（文本 90 秒 / 视觉 180 秒）
和一键打断（见下）。

## 4. 密钥怎么存

- 只存在本地 SQLite（`out/platform/jobs.db`），**接口不回传明文**，
  列表只显示末四位（`…7890`）。
- 编辑配置时**留空 = 不修改**（只有显式清空才会删掉密钥）。
  这条是防「改个名字顺手把密钥清了，下次调用才 401」。
- 密钥不进日志、不进报告。
- 注意：本地库没有加密（平台没有安全存放主密钥的地方）。共享这台机器的人能看到它，
  按这个前提使用。

## 5. 出问题怎么判断

| 现象 | 看法 |
|---|---|
| 列表上标「不支持看图」 | 模型本身不支持，换多模态模型；不是故障 |
| 「测试」返回 401 | 密钥无效 / 过期 / 没配额。返回体会原样带出来 |
| 「测试」显示可达但检测时回退 | 看任务日志里的具体报错，通常是模型名不对或超上下文 |
| 一直「AI 已启用」但报告没 AI 痕迹 | 看报告基本信息里的「AI 调用情况」：0 次调用说明环节开关没开 |

**没启用任何配置 = AI 关闭**：provider 是 `none`，连请求都不发。
这和「配了但连不上」必须分开 —— 报告要能回答「AI 到底有没有参与」。

---

## 6. 停止与打断

点「停止」时，**在途的模型调用会被立刻打断**（取消令牌 + 后台线程轮询，
不会等你等到 90 秒超时）。注入调用如果卡在设备上，最多 1 分钟强制收工。

打断只作用于「当前任务」，不会连累队列里的下一个 —— 这一点专门处理过：
任务开局和结束时各复位一次取消标记。

## 7. 开发用：Agent 中继（不需要任何模型服务）

没有 GPU、也不想为试跑一次就申请云端 key 时：

```
类型：agent
```

平台不连任何服务，把每个 AI 请求（含截图）落盘到 `out/ai_relay/<会话>/`，
人工（或对话里的 AI）看完图写好答案放回去，平台接着跑。

```bash
python tools/ai_relay.py list                 # 有哪些待回答的请求
python tools/ai_relay.py show <id>            # 看提示词和截图路径
python tools/ai_relay.py answer <id> --file a.json
```

中继有 900 秒等待上限，超时就回退确定性策略，不会把整轮检测卡死。
