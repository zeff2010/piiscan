动态采集：安装 APK 并清数据（才会走首启、弹窗才出现）→ 自动点开政策入口取正文 → 冷启动注入插桩并自动遍历分步截图。四个档位各自成套调整耦合参数 （时长 150 / 300 / 900 / 3600s，首启 45 / 30 / 45 / 60s， 单 hook 20 / 20 / 40 / 80 条，总事件 4k / 5k / 12k / 40k， 截图 20 / 24 / 60 / 160，复现 120 / 150 / 300 / 600s， 单屏点击上限 20 / 24 / 30 / 45 / 60，列表上拉 1 / 2 / 2 / 3 / 5 次）—— 只加时长不加上限，事件会先被截断；只加上限不加时长，遍历走不到深层。
档位差别不只在时长：1 档不点同意，取到政策后仍会在未同意状态下 点开各个界面（点「不同意 / 仅浏览」进主界面也算，只有同意不点）， 2 档不登录、只点到二级目录，3、4 档才尝试微信快捷登录 / 手机号验证码登录。
登录辅助：走到登录页会先勾「我已阅读并同意」、再代填号码并点「获取验证码」， 验证码默认直接从测试机短信收件箱读取（测试机 SIM 就在机内，需 root）； 读不到时才退回人工——在该任务的「短信验证码」框里填。号码脱敏进报告 （133****0822），验证码不落库。
若点击后设备一条短信都没收到，报告会写明「发码请求未真正发出」， 而不是含糊的「未收到验证码」——两者对复核员意思完全不同。
复现：自动清数据后按首轮记录的点击路径逐步重放（不调模型，比首轮快很多）—— 判据再次出现的保留确证，没再出现的降为疑似； 重放没走完或没采到数据时状态不变，报告写明原因（不拿"没走到"当"没复现"）。
AI 增强 （用大模型替代关键词匹配与盲点式遍历；连哪个模型在「系统状态」里配）
模型服务不在这里配。用哪个模型（本机 Ollama / DeepSeek / 内网接口） 是平台级设置，去 系统状态 → AI 模型服务 里添加或切换； 这里只决定这一个任务开哪些 AI 环节。
看截图定位入口能认出「服务协议及个人信息处理规则」这类关键词覆盖不到的写法， 还能指出正文里带颜色的超链接（它在界面结构里根本不是独立元素，只有看图才发现）； 政策深读抽取声明收集的信息类型、注销路径、投诉渠道并追链子文档； AI 指挥遍历把每步截图交给模型决定点哪里。前两项需多模态，第三种最耗时 —— 启用后单次检测可能 10~40 分钟（速度不是本平台的优化目标）。
每问一次模型都要等一次推理：把「每几步问一次」调到 3~5 并设次数上限， 可在几乎不损失效果的前提下压成本；中间步骤照常走规则遍历。
若当前启用的是纯文本模型（如 deepseek-v4-pro），两项看图环节会自动回退到规则策略 —— 这不是故障。DeepSeek 里能看图的是 deepseek-flash，换一个就行。
检测在后台队列中执行。启用动态采集时总耗时约 1.5–3 分钟（安装 + 首启观测 + UI 遍历）；仅静态与政策分析约 20–60 秒。提交成功后会自动跳到「任务列表」。
